# MVP 范围与执行计划草案

状态：MVP 范围已确认  
用途：把已确认的产品、玩法、课程、页面和 UI 规则收束为可执行的第一版开发范围。

## 1. MVP 定义

已确认：首案完整闭环。

范围：

- 从警官学院官网首页开始。
- 创建小警探身份。
- 完成“导航机器人迷路案”。
- 获得导航修复勋章。
- 解锁城市地图并看到中央广场开放。

优点：

- 范围最可控。
- 最能验证“学习题目 + 破案剧情 + Boss + 奖励”的核心循环。
- 能避免继续堆一堆半成品页面。

风险：

- 三门课程暂时只落地数学。
- 城市地图和语文/英语只是预告，不是完整可玩。

明确不选：

- 不选“三科各一个案件”。
- 不选“首页 + 地图 + 多个原型页面”。
- 不以页面数量作为 MVP 成功标准。

## 2. MVP 必做范围

以下为已确认范围。

### 2.1 页面

必须实现：

1. 警官学院官网首页。
2. 创建小警探。
3. 首案接案页。
4. 训练场线索任务页。
5. 独立线索板。
6. 轻量推理页。
7. Boss 战页。
8. 勋章奖励页。
9. 城市地图首屏。

### 2.2 首案内容

必须实现：

- 案件：导航机器人迷路案。
- 学科：数学。
- 知识点：东、南、西、北。
- 地图：中心分叉路线。
- 题库：已审核通过的 8 道题。
- 线索：方向灯、路线芯片 1、路线芯片 2、故障原因线索。
- Boss：混乱导航机器人，3 道挑战。
- 奖励：导航修复勋章、XP、城市地图解锁。

### 2.3 交互

必须实现：

- 创建昵称，提供随机昵称按钮。
- 3 个动物头像选择。
- 训练场 4 个线索节点按顺序解锁。
- 地图节点点击进入任务。
- 方向按钮 / 选择题 / 地图节点点击。
- 答错给提示并允许重试。
- 独立线索板点击线索查看一句解释。
- Boss 无限重试。
- 奖励后进入城市地图。

### 2.4 数据

必须实现：

- 小警探档案：昵称、头像。
- 首案进度：当前题、已收集线索、Boss 步骤、是否通关。
- 奖励数据：XP、导航修复勋章。
- 城市地图解锁状态：中央广场开放，2 个区域锁定。

建议：

- MVP 可先使用 localStorage。
- 不接云端账号。
- 不收集真实姓名、学校、班级、照片。

### 2.5 视觉资产

必须实现最低可用版：

- 学院首页背景。
- 牛局长 / 牛队长。
- 3 个小警探头像。
- 训练场地图背景与节点。
- 混乱导航机器人。
- 4 个线索图标。
- 导航修复勋章。
- 城市地图首屏。

若图像生成工具暂不可用：

- 可先使用参考图 + 占位资产开发结构。
- 但不得把参考图整张当最终 UI。
- 资产生成恢复后替换占位图。

## 3. 明确不做

MVP 首版不做：

- 三科完整案件。
- 语文和英语正式关卡。
- 真实多人社交。
- 排行榜。
- 付费系统。
- 老师后台。
- 家长后台。
- 云端账号。
- AI 自由对话。
- 复杂 3D 城市。
- 头像装扮系统。
- 完整错题本。
- 语音朗读。
- 长时间连续学习奖励。
- 对外发布授权确认。

## 5. 里程碑草案

### M1 数据与流程骨架

交付：

- 首案 8 道题转成数据。
- 页面路由 / 状态机。
- localStorage 进度保存。
- 无美术或低保真也能跑通流程。

验收：

- 能从首页走到城市地图。
- 刷新后进度不丢。

### M2 首案交互可玩

交付：

- 创建小警探。
- 地图节点按顺序解锁。
- Q1-Q8 可作答。
- 错误提示和重试。
- 线索板可点击。
- Boss 3 步修复。

验收：

- 不看代码也能完成首案。
- 答案和解释正确。

### M3 视觉资产接入

交付：

- 接入首批正式或占位资产。
- 页面按动画电影感视觉方向统一。
- 背景、角色、道具、UI 分层实现。

验收：

- 不使用整张高保真图热区当页面。
- 文字和按钮不重叠。

### M4 试玩修正

交付：

- 桌面和平板尺寸检查。
- 修复卡点、文字过长、按钮不明显等问题。
- 记录试玩反馈。

验收：

- 二年级孩子在轻量引导下可完成首案。
- 首案时长目标 8-12 分钟。

## 6. MVP 验收标准

产品：

- 孩子能从首页理解“加入警官学院”。
- 孩子能创建小警探。
- 孩子能完成导航机器人迷路案。
- 孩子能获得导航修复勋章。
- 孩子能看到城市地图已解锁。

教育：

- 8 道题只考东、南、西、北。
- 每道题有答案、提示、解释。
- 错误反馈不羞辱孩子。
- 题目与训练场、机器人、路线线索相关。

交互：

- 主要点击目标不小于 44px。
- 每屏只有一个主要任务。
- 错题可重试。
- Boss 不失败惩罚。

视觉：

- 分层资产 + DOM 组件。
- 关键文字不在图片里。
- 页面不依赖整张设计图热区。
- 桌面和平板为首轮硬验收尺寸，不重叠、不溢出。
- 手机不作为首轮硬验收，但不能严重横向溢出或完全不可用。

工程：

- 构建通过。
- 进度可保存。
- 题目数据结构化。
- 新增题目不需要改页面组件。

## 7. 开发恢复条件

建议满足以下条件后恢复开发：

- MVP 范围确认。
- `07-mvp-scope.md` 冻结。
- 首案题库已审核通过。已完成。
- 信息架构已确认。已完成。
- UI / 美术方向已确认。已完成。
- 资产生成不可用时，已确认允许先使用占位资产，但必须遵守分层规则。

## 8. 资产占位规则

已确认：允许使用占位资产恢复开发。

规则：

- 占位资产也必须按背景、角色、道具、UI 分层。
- 不允许用整张高保真参考图作为最终页面背景热区。
- 关键文字、按钮、题干、答案、进度、节点状态必须使用 DOM。
- 占位资产文件名应带 `placeholder` 或放入清晰目录，方便后续替换。
- 正式资产生成后逐项替换，并做页面截图验收。
