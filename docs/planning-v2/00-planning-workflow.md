# 规划流程与冻结规则

## 1. 为什么暂停开发

当前页面效果与预期有偏差，主要原因不是单个页面实现问题，而是以下内容尚未冻结：

- 项目的世界观边界：直接使用疯狂动物城，还是原创动物城市。
- 第一版 MVP 的核心目标：验证视觉氛围、学习效果，还是完整破案闭环。
- 游戏主线：孩子为什么加入学院，导师如何带领，Boss 与案件如何推进。
- 页面职责：每个页面到底是宣传、叙事、学习、推理，还是成长反馈。
- 美术资产规则：哪些是背景，哪些是角色，哪些必须是可交互 DOM。

在这些内容未确认前继续开发，会导致页面反复返工，题库、剧情和 UI 互相拉扯。

## 2. 推荐推进节奏

### 第 1 轮：项目方向冻结

目标：确定项目的北极星，不写细玩法。

需要确认：

- 世界观 / IP 方向。
- 核心用户与使用场景。
- MVP 第一版最想验证什么。
- 项目的成功标准。

交付物：

- `02-product-north-star.md` 冻结版。
- `01-decision-workbook.md` 更新决策结果。

### 第 2 轮：游戏框架冻结

目标：确定游戏像什么，而不是页面长什么样。

需要确认：

- 主线剧情。
- 学员成长路径。
- 案件结构。
- 线索、推理、Boss、结案报告的关系。
- 勋章与等级系统的作用。

交付物：

- `03-game-design.md`。
- 第一版核心循环图。

### 第 3 轮：课程框架冻结

目标：确定学习内容如何自然嵌进破案。

需要确认：

- 语文、数学、英语三门课的定位。
- 每门课的题型边界。
- 教材知识点映射方式。
- 每个案件覆盖几个知识点。
- 题目解释和错题复盘标准。

交付物：

- `04-curriculum-design.md`。
- 题目数据模板。

### 第 4 轮：页面与交互冻结

目标：确定信息架构，再做视觉。

需要确认：

- 首页、入学、地图、案件、题目、推理、结案、勋章墙的页面职责。
- 每个页面的主操作。
- 用户从第一次打开到完成首案的路径。
- 低龄用户的文字量、按钮数量和提示规则。

交付物：

- `05-information-architecture.md`。
- 低保真流程。

### 第 5 轮：美术与 UI 冻结

目标：让 imagegen / 设计图 / 前端实现使用同一套规则。

需要确认：

- 视觉风格关键词。
- 场景、角色、道具、徽章的资产分层。
- 背景图不得承载关键 UI 文案。
- 真实交互元素必须由前端 DOM 实现。
- 响应式验收尺寸。

交付物：

- `06-ui-art-direction.md`。
- 关键页面高保真设计规范。

### 第 6 轮：MVP 范围冻结

目标：明确第一版做什么、不做什么。

需要确认：

- MVP 案件数量。
- 是否三门课都进入 MVP。
- 是否需要登录 / 本地进度 / 家长报告。
- 哪些内容只进 backlog。

交付物：

- `07-mvp-scope.md`。
- 开发任务拆分。

## 3. 冻结规则

每个决策使用三种状态：

- `待确认`：不能进入开发。
- `已确认`：可以作为设计和开发依据。
- `需复盘`：已经临时使用，但后续必须重新确认。

所有影响范围、剧情、课程、技术架构、美术方向的选择，都必须记录到 `01-decision-workbook.md`。

## 4. 开发恢复条件

至少满足以下条件后，才恢复下一轮 MVP 开发：

- 第 1 轮项目方向已确认。
- 第 2 轮游戏框架已确认。
- 第 4 轮页面职责已确认。
- 第 5 轮 UI / 美术资产规则已确认。

如果只做探索性原型，必须明确标记为 `探索`，不能直接进入正式版本。

## 5. 交接规则

任何人接手项目时，必须先阅读：

1. 当前冻结的规划文档。
2. `01-decision-workbook.md` 中的已确认决策。
3. 当前 MVP 范围和不做清单。
4. 最近一次试玩反馈。

未冻结事项不允许被开发人员自行补齐，只能提出建议等待确认。
