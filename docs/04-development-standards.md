# 开发与内容规范

日期：2026-05-11  
适用范围：警官学院闯关学习游戏的前端、内容、素材和测试。

## 1. 总体规范

- 先保证学习闭环，再做视觉和动效增强。
- 页面组件不直接写死案件、题目、勋章、等级数据。
- 题目数据必须有答案、解释、提示、知识点。
- 每次新增功能都要能在本地构建通过。
- 不引入新依赖，除非能明确减少复杂度。

## 2. 项目结构建议

当前项目已有 `screens/` 和 `components/`。建议逐步调整为：

```text
src 或项目根
  components/
    layout/
    game/
    mission/
    ui/
  screens/
  data/
    missions/
    medals.ts
    ranks.ts
    curriculum.ts
  domain/
    progress.ts
    scoring.ts
    mission.ts
  hooks/
  styles/
  docs/
```

如果短期不迁移 `src/`，也要保持同样边界。

## 3. 数据模型规范

案件 ID：

- 格式：`case-区域-序号`，如 `case-canal-001`。

题目 ID：

- 格式：`q-案件-序号`，如 `q-canal-001-03`。

勋章 ID：

- 格式：`medal-类型-名称`，如 `medal-case-spring-detective`。

基础类型：

```ts
type Subject = 'chinese' | 'math' | 'reasoning';
type Difficulty = 'A' | 'B' | 'C';
type QuestionType =
  | 'choice'
  | 'drag-sort'
  | 'match'
  | 'map-route'
  | 'input'
  | 'read-and-find';

type Mission = {
  id: string;
  title: string;
  districtId: string;
  subject: Subject;
  summary: string;
  curriculumTags: CurriculumTag[];
  clueQuestionIds: string[];
  bossQuestionIds: string[];
  reward: Reward;
};
```

## 4. 组件规范

- `screens/` 负责页面组合。
- `components/game/` 负责游戏展示组件，如地图卡、Boss 血条、线索板。
- `components/mission/` 负责题型组件。
- `domain/` 负责纯逻辑，如计分、升级、解锁条件。
- `data/` 只放配置和 mock 数据。

题型组件必须做到：

- 输入题目数据。
- 输出作答结果。
- 不知道具体案件剧情。
- 不直接修改全局进度。

## 5. UI/UX 规范

低龄儿童界面：

- 主要按钮高度不低于 44px。
- 单屏主操作不超过 3 个。
- 题干短句优先，复杂说明拆成步骤。
- 错误反馈用鼓励和提示，不使用羞辱性文案。
- 限时只用于紧张感，不作为主要惩罚。
- 提供音效开关、动效弱化方案。

视觉风格：

- 地图是主界面核心，不做纯卡片堆叠主页。
- 卡片只用于案件、勋章、题目等独立对象。
- 不把多个卡片嵌套成复杂面板。
- 移动端优先检查文字溢出。
- 若未授权，不使用 Disney/Zootopia 官方角色、图像、标志、名称。

## 6. 内容规范

每道题提交时必须包含：

- 年级：二年级下册。
- 学科。
- 教材版本。
- 单元。
- 知识点。
- 难度。
- 题干。
- 正确答案。
- 错误选项设计说明。
- 提示。
- 答案解释。
- 场景关联。

禁止：

- 大段复制教材课文。
- 使用超过二年级理解范围的抽象术语。
- 为了剧情牺牲答案唯一性。
- 使用“你太笨了”等负面反馈。
- 用未授权影视截图或角色图作为正式素材。

## 7. 计分与成长规范

计分规则集中在 `domain/scoring.ts`。

建议规则：

- 答对线索题：10 XP。
- 首次答对奖励：5 XP。
- 使用提示后答对：8 XP。
- 完成 Boss 战：30 XP。
- 完成案件：50 XP。
- 复盘错题：10 XP。

等级规则集中在 `data/ranks.ts`，不要散落在页面中。

勋章规则集中在 `data/medals.ts`，每枚勋章必须有：

- 解锁条件。
- 展示名称。
- 描述。
- 图标/素材。
- 是否隐藏。

## 8. 测试规范

每次开发完成至少检查：

- `npm run build`。
- 首页到结案完整流程。
- 刷新后进度保留。
- 移动端宽度 375px 不溢出。
- 桌面端 1440px 主要界面不空洞。
- 错题答案和解释正确。

题目审核需要人工检查：

- 答案唯一。
- 解释正确。
- 干扰项合理。
- 不超纲。
- 与剧情有关。

## 9. 交接规范

每个功能 PR 或阶段交付必须说明：

- 改了哪些页面/组件。
- 新增了哪些数据文件。
- 如何试玩。
- 已知问题。
- 测试结果。

每个案件交接必须提供：

- 案件简介。
- 课程目标。
- 题目清单。
- 奖励。
- 试玩路径。
- 内容审核状态。

## 10. 发布前检查清单

功能：

- 新用户可完成入学。
- 地图可选择案件。
- 至少 3 个案件完整可通关。
- 勋章、等级、XP 正常更新。
- 结案报告正确展示。

内容：

- 所有题目有解释。
- 所有题目通过教研审核。
- 无教材大段复制。
- 无未授权正式素材。

工程：

- 构建通过。
- 控制台无明显错误。
- 页面移动端可用。
- 进度数据有兼容处理。

合规：

- 不收集真实姓名、学校、照片等敏感信息。
- 对外版本完成 IP 检查。
- 素材来源可追溯。
