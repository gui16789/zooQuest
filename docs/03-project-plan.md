# 项目计划

日期：2026-05-11  
目标：用可控范围完成“警官学院官网 + 地图闯关 + 学习闭环”的 MVP。

## 1. 交付策略

先做单机可玩闭环，再做内容扩展和后台。

原因：

- 当前原型已经有页面骨架，最短路径是把静态页面改成数据驱动的关卡系统。
- 教育游戏的最大风险是玩法和知识点结合不好，先用 3-5 个案件验证。
- 后台、账号、AI、多人都不是第一阶段成败关键。

## 2. 阶段计划

### P0：规划与规范，1-2 天

交付物：

- PRD。
- 课程知识点映射。
- 项目计划。
- 开发规范。
- 内容模板。

验收：

- 能说明 MVP 做什么、不做什么。
- 每个首批案件能追溯到教材知识点。
- 开发和内容同学能按模板新增任务。

### P1：信息架构与数据模型，2-3 天

交付物：

- 路由/页面状态重构方案。
- 学员进度数据模型。
- 案件、题目、勋章、等级配置模型。
- 首批 mock 数据。

验收：

- 页面不再硬编码主要案件内容。
- 能从数据生成地图卡片、案件任务、结案报告。
- localStorage 可保存进度。

### P2：MVP 游戏闭环，5-7 天

交付物：

- 官网首页入学流程。
- 学员中心。
- 地图案件选择。
- 线索任务交互。
- Boss 战。
- 结案报告。
- 勋章墙。
- 学习手册/错题回看。

验收：

- 新用户可以从首页进入案件并完成结案。
- 至少 3 个完整案件可玩。
- 每个案件至少 5 个线索任务和 1 个 Boss 战。
- 构建通过。

### P3：内容扩展与教研审核，5-10 天

交付物：

- 8-12 个案件。
- 每个数学单元至少 1 个案件。
- 每个语文方向至少 1 类题型。
- 内容审核表。

验收：

- 所有题目有知识点、难度、答案、解释、提示。
- 题目不直接复制教材课文或图片。
- 二年级孩子试玩后主要交互无需成人解释。

### P4：体验优化与上线准备，3-5 天

交付物：

- 移动端适配。
- 可访问性优化。
- 音效/动效控制。
- 家长可读报告。
- IP 替换或授权确认清单。

验收：

- 手机、平板、桌面基础可用。
- 单局时长可控。
- 对外版本没有未授权角色、名称、图像。

## 3. 建议里程碑

| 里程碑 | 时间 | 判断标准 |
| --- | --- | --- |
| M1 规划冻结 | 第 2 天 | 文档齐全，MVP 范围明确 |
| M2 数据驱动原型 | 第 5 天 | 地图/案件/题目从配置渲染 |
| M3 首个案件通关 | 第 8 天 | 完成从入学到结案闭环 |
| M4 三案件 MVP | 第 12 天 | 语文、数学、推理各有完整案例 |
| M5 试玩版 | 第 18 天 | 有 8+ 案件，完成体验修正 |

## 4. 分工建议

产品/项目负责人：

- 控制范围。
- 维护 PRD 和里程碑。
- 组织试玩反馈。

教研/内容负责人：

- 维护课程映射。
- 编写题目、提示、解释。
- 审核年级适配和教材边界。

前端负责人：

- 页面组件和状态管理。
- 题型交互组件。
- 响应式和可访问性。

视觉/素材负责人：

- 原创角色/地图/勋章风格。
- 避免未授权 IP 资产。
- 管理素材命名和授权记录。

测试负责人：

- 验证闯关流程。
- 验证题目答案。
- 验证移动端和构建。

## 5. 进度跟踪方式

建议维护一个任务看板，字段如下：

- ID。
- 类型：功能 / 内容 / 设计 / 测试 / 风险。
- 所属阶段。
- 负责人。
- 状态：Todo / Doing / Review / Done / Blocked。
- 验收标准。
- 关联文件。

每个案件单独建卡，拆成：

- 剧情梗概。
- 知识点。
- 题目数据。
- UI 联调。
- 教研审核。
- 试玩反馈。

## 6. 决策记录规范

所有会影响后续开发的选择要记录在 `docs/decision-log.md`，包括：

- 是否继续使用授权 IP。
- 三门课程最终命名。
- 数据存储方式。
- 首批地图数量。
- 是否需要登录。
- 是否引入后端。

记录格式：

```md
## YYYY-MM-DD 决策标题

- 背景：
- 选项：
- 决策：
- 影响：
- 负责人：
```

## 7. 风险管理

| 风险 | 等级 | 触发信号 | 应对 |
| --- | --- | --- | --- |
| IP 未授权 | 高 | 准备对外发布或商业化 | 改原创 IP 或取得授权 |
| 内容质量不足 | 高 | 孩子只点按钮不理解知识 | 教研审核 + 结案解释 |
| 范围过大 | 高 | 同时推进后台/AI/多人 | MVP 冻结，新增需求进 backlog |
| 低龄用户不会操作 | 中 | 试玩中频繁卡住 | 降低步骤，强化图标和语音/提示 |
| 题目维护困难 | 中 | 新增案件要改多个组件 | 数据驱动，组件只处理题型 |
| 移动端体验差 | 中 | 小屏文字溢出或按钮太小 | 每阶段做移动端截图检查 |

## 8. Backlog 优先级

P0 必须：

- 数据驱动案件。
- 3 个完整案件。
- 等级/XP/勋章。
- 结案报告。
- 错题回看。

P1 应该：

- 8-12 个案件。
- 原创角色/地图资产。
- 家长报告。
- 音效开关。
- 难度自适应的基础规则。

P2 可以：

- 老师后台。
- 云端账号。
- AI 导师答疑。
- 语音朗读。
- 更多课程。
